# WorkPulse AI

> An interactive AI-powered workplace simulation platform for exploring task performance, algorithmic supervision, and observable behavioral patterns in a simulated work environment.

## Overview

**WorkPulse AI** is an interactive workplace simulation platform developed as a **Projet de Fin d'Année (PFA)** in Software Architecture Engineering.

The platform places users in a simulated professional environment where they perform workplace-oriented tasks while interacting with **ARIA**, a virtual AI supervisor. During the simulation, the system collects task and interaction telemetry, evaluates task performance using deterministic rules, analyzes observable behavioral patterns, and presents the results through a final report and debriefing interface.

### Core capabilities

- Interactive workplace simulation
- Automatic task generation and assignment
- AI-supported virtual supervision
- Task-level performance evaluation
- Interaction telemetry
- Behavioral evaluation
- Recommendation generation
- Simulation history and session persistence
- Final reporting and debriefing

> **Scope note:** WorkPulse AI is a simulation and software-engineering project. Its behavioral indicators are computational proxies derived from observable interaction data and are not intended to represent clinical, psychological, or neuroscientific measurements.

## Objectives

The main objectives are to:

- Simulate selected workplace situations in an interactive environment.
- Introduce AI-based supervision through a virtual manager.
- Automatically generate task instances from predefined templates.
- Collect relevant task and interaction data during simulation.
- Evaluate task execution using deterministic rules.
- Calculate observable performance and behavioral indicators.
- Provide contextual recommendations based on available data.
- Present a structured post-simulation report.
- Provide a controlled environment for experimenting with AI-supported workplace supervision.

## Core Features

### Automatic Task Generation

The task engine generates task instances during a simulation rather than relying on a single hardcoded task.

The general process is:

1. Select a task type.
2. Select a corresponding task template.
3. Generate a task instance.
4. Assign the task to the active session.
5. Allow the user to perform the task.
6. Evaluate the result.
7. Record task and interaction telemetry.

Supported task categories include:

- Data Validation
- Document Organization
- Email Writing
- Urgent Requests
- Email Prioritization

### ARIA — AI Virtual Supervisor

**ARIA** is the virtual supervisor within the simulated workplace.

ARIA can:

- Provide contextual managerial messages.
- Send reminders and interventions.
- React to available user activity and simulation state.
- Adapt supervisory interactions according to the current simulation context.
- Generate natural-language managerial responses through the AI integration layer.

The analytical layer remains separate from the language-generation component: behavioral scores and indicators are calculated by deterministic application logic rather than being directly generated by the language model.

### Task Evaluation

Each task produces structured results after execution. Depending on the task type, evaluation can consider:

- Completion
- Response time
- Errors
- User decisions
- Task-specific correctness
- Priority decisions
- Other recorded interaction data

These results contribute to the telemetry and behavioral-evaluation pipeline.

### Behavioral Evaluation

WorkPulse AI transforms collected simulation data into structured behavioral indicators related to:

- Performance
- Accuracy
- Pace/productivity
- Fatigue-related patterns
- Performance evolution
- Error evolution
- Interaction behavior

The system also applies data-sufficiency conditions to avoid interpreting observations when the available sample is insufficient.

These indicators are **computational measures based on simulated interactions**, not psychological or clinical diagnoses.

### Recommendation Engine

The recommendation engine evaluates available behavioral indicators and session data to determine whether a recommendation rule should be triggered.

The system includes explicit data-sufficiency checks so recommendations requiring trends or evolution are not triggered when there are not enough observations to support them.

### Email Prioritization

The Email Prioritization task simulates a workplace inbox containing messages with different levels of importance and urgency.

The user assigns priorities to the messages, after which the backend evaluates the decisions using a deterministic priority-evaluation mechanism. The resulting task-level data can be incorporated into the behavioral analysis.

### Simulation History

Users can review previous simulation sessions, identify incomplete sessions, continue an interrupted simulation, and access completed session results. Session information is persisted through the backend and database layer.

### Behavioral Report and Debriefing

After a simulation, the platform presents a structured report containing relevant session results, including:

- Performance indicators
- Behavioral indicators
- Observed patterns
- Recommendations
- Task-related results
- Debriefing information

## Getting Started

### Prerequisites

- Git
- Python 3.x
- Node.js
- npm
- PostgreSQL
- OpenAI API key for AI-powered ARIA interactions

### Clone

```bash
git clone <YOUR_REPOSITORY_URL>
cd WorkPulse-AI
```

### Backend Setup

```bash
cd backend
python -m venv .venv
```

Windows:

```bash
.venv\Scripts\activate
```

Linux/macOS:

```bash
source .venv/bin/activate
```

Install dependencies:

```bash
pip install -r requirements.txt
```

### Environment Configuration

Create a `.env` file in the backend directory using the variables required by the application.

Typical configuration:

```env
DATABASE_URL=postgresql://USER:PASSWORD@localhost:5432/workpulse
OPENAI_API_KEY=your_openai_api_key
```

Additional variables may be required by the current authentication and application configuration.

**Never commit secrets or credentials to GitHub.**

### Database Setup

Create a PostgreSQL database, for example:

```sql
CREATE DATABASE workpulse;
```

Configure the database connection through the backend environment variables.

Run the database initialization or migration process required by the current backend configuration.

### Frontend Setup

```bash
cd frontend
npm install
npm run dev
```

Vite will display the local development URL in the terminal.

### Running the Backend

Use the project's configured application entry point. For a FastAPI application, a typical development command is:

```bash
uvicorn app.main:app --reload
```

If the repository uses a different entry point, use the command defined by the current backend configuration.

## Deterministic Analysis and AI Separation

A key design principle is the separation between **deterministic analytical logic** and **AI-generated language**.

```text
User Interaction
       |
       v
Telemetry Collection
       |
       v
Deterministic Evaluation
       |
       +--------------------+
       |                    |
       v                    v
Behavioral Indicators   Recommendations


ARIA Context
       |
       v
OpenAI Service
       |
       v
AI-generated Managerial Message
```

The language model is not responsible for directly calculating behavioral scores or analytical indicators. This keeps the analytical layer explicit and testable while allowing ARIA's natural-language interaction to remain dynamic.

## Methodology Notes

Behavioral indicators are based on observable simulation data such as task performance and interaction telemetry.

They are computational proxies within the simulation and are not intended to provide:

- Clinical assessment
- Psychological diagnosis
- Neuroscientific measurement
- Medical evaluation

Time-efficiency and cognitive-load-related indicators are based on task execution time and the adapted deadline used by the simulation. They should therefore be interpreted as task-load proxies rather than direct measurements of cognitive or psychological states.

## Limitations

The current implementation has several limitations:

- Behavioral indicators have not been empirically calibrated through a large participant study.
- The indicators are computational proxies and should not be interpreted as psychological or clinical measurements.
- Browser-level end-to-end validation against a complete live deployment is limited.
- The current task library represents a controlled selection of workplace scenarios.
- The project does not provide evidence for generalizing simulated behavioral results to real workplace populations.
- Further user evaluation would be required to assess usability and realism.
