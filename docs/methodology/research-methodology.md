# Research Methodology

## Research objective

WorkPulse AI investigates whether a controlled digital work simulation, supervised by an adaptive algorithmic agent, can produce interpretable behavioral indicators of how a participant's work pattern evolves under simulated workplace pressure — without asserting a clinical or psychological measurement of that participant.

## Simulation principle

The platform simulates workplace activity under adaptive algorithmic supervision. A participant performs a fixed sequence of controlled digital work tasks (data validation, document classification, email composition, and an urgent-request decision) while the system records behavioral interactions (task timing, submissions, corrections) and periodically invites the participant to self-report a perceived pressure level. An AI supervisor ("ARIA") observes the same telemetry and adapts its own communication tone through a deterministic state machine, independent of the analytical pipeline described below.

## Participant interaction

A participant authenticates, starts a session, and is presented with exactly one active task at a time, determined entirely by the backend. The participant engages with the task's real interface (checkboxes, drag-and-drop classification, a text editor, or a multiple-choice decision, depending on task type), submits it, and is immediately presented with the next task in sequence — or, after the sixth task, transitioned to a debriefing state and shown a report.

## Task sequence

The default sequence is fixed and backend-configured: two `data_validation` tasks, two `document_organization` tasks, one `email_writing` task, and one `urgent_request` task, within a 1800-second (30-minute) global session budget. See `docs/architecture/session-and-task-engine.md` for the exact implementation.

## Data collection

Three categories of data are collected, and are never conflated in reporting:

1. **Objective/behavioral data** — timestamps, submitted answers, computed correctness, telemetry events (see `docs/architecture/telemetry-and-analytics.md`).
2. **Self-reported data** — the participant's own 1–5 declared pressure level, collected on demand, never inferred from behavior.
3. **System-generated indicators** — every derived metric and behavioral-evaluation classification computed from categories 1 and 2.

## Derived indicators

Execution time, accuracy, error rate, pace efficiency, workflow transition time, a productivity index, a cognitive-load proxy, and a heuristic fatigue indicator are all computed deterministically from the objective/behavioral data. Full formulas: `docs/methodology/metrics-and-indicators.md`.

## Behavioral interpretation

A separate layer compares the first and second half of the session's task sequence for each derived indicator, classifies the direction of change (e.g. "declining," "accelerating"), and applies a small set of deterministic rules to describe how multiple indicators co-occur (e.g. slower execution alongside declining accuracy). This layer produces descriptive labels only — see `docs/methodology/behavioral-model.md`.

## Adaptive supervision

In parallel, and independently of the interpretation layer above, a finite-state machine computes a pressure score from the same underlying telemetry and adjusts ARIA's communication tone across four bands (`bienveillant`/`neutre`/`exigeant`/`intrusif`). A large language model is used only to phrase the already-decided tone and trigger into a short natural-language message — it does not decide the tone, the trigger, or any analytical output. See `docs/architecture/aria-architecture.md`.

## Final report

At the end of a session, the participant is shown a report containing the quantitative results, the behavioral interpretation, and a set of deterministic, rule-based recommendations. No part of the current report is generated by a language model.

## Separation between observation and interpretation

This is a structural property of the codebase, not a stylistic choice: raw observations (`InteractionMetric`, `Task` timestamps, `StressDeclaration`) are stored as-is; every derived metric is computed by a named, inspectable function over those observations; every behavioral-interpretation label is computed by a further, separately named function over the derived metrics. No step skips a layer, and no derived value is ever presented as if it were a raw observation.

## Separation between deterministic analytics and LLM generation

```
                  DETERMINISTIC CORE
   Task correctness · Task sequence · Timing · Telemetry
   Metrics · Behavioral evaluation · Recommendations · FSM · ARIA state

                  LLM LAYER
   Natural-language generation · Contextual wording
```

*Le LLM intervient comme composant de génération linguistique, et non comme autorité décisionnelle sur les résultats analytiques de la simulation.*

This separation was verified directly against the source code (see `docs/architecture/openai-integration.md`'s "what the LLM is not allowed to decide" section and the architectural independence checks in the final architecture audit): no analytical, scoring, sequencing, or state-machine output is ever assigned from an OpenAI response anywhere in the codebase.

## Academic claim discipline

This documentation set, and any report or presentation built from it, must avoid claims the implementation cannot support:

| Avoid | Use instead |
|---|---|
| "The system measures the user's cognitive load." | "The system estimates a temporal cognitive-load proxy based on the ratio of time used to time allocated." |
| "The system objectively measures stress." | "The participant declares a perceived pressure level on a 1–5 scale." |
| "The system diagnoses the participant's psychological state." | "The behavioral evaluation identifies descriptive, non-diagnostic patterns in observed task behavior." |
| "The system detects fatigue." | "A heuristic fatigue indicator combines performance decline, slowdown, error concentration, and declared pressure." |
| "The LLM decides how stressed the participant is." | "The LLM generates contextual natural-language messages once the tone and trigger are already decided by deterministic backend logic." |

**The system does not prove psychological causality, does not perform clinical stress detection, and does not constitute a validated psychological measurement instrument.** Every quantitative and behavioral output is a simulation indicator computed from a fixed, documented formula or a self-report, and must be presented as such.
